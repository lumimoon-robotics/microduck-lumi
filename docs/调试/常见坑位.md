# 常见坑位与排查

> **本教程原则**：**全网已知坑位汇总**——遇到问题先来这里查。  
> **来源**：`fanhao375/microduck-replica` 的 `踩坑记录.md` + `sim336/OptiDuck` 的 v1.04 release notes + `JoyandAI/OpenMicroDuck` 的 issues + `microduck-lumi` 项目自身 + D-Robotics 论坛 五源汇总。

## 一、舵机相关

### 1.1 总线扫描不到任何舵机

| 现象             | 可能原因                                                        | 排查方法                                                                                                                          |
| -------------- | ----------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| Scan 不到 1 颗    | 1) 飞特脚序接反<br />2) URT-2 串口选错<br />3) 适配器没上电<br />4) 总线波特率不对 | 1) 逐根核对线序（**飞特 1=Signal 2=Vcc 3=GND**）<br />2) `ls /dev/ttyUSB*` 确认串口<br />3) 适配器绿灯亮？<br />4) 飞特默认 1 Mbps，URT-2 自带软件默认 1 Mbps |
| Scan 反复出现 / 消失 | 多颗出厂 ID 冲突                                                  | 一次只接 1 颗，**先逐颗配 ID 再串联**                                                                                                      |
| Scan 偶尔掉线      | 1) 线材问题<br />2) 阻抗不匹配<br />3) 驱动能力不足                        | 1) 换特软硅胶线（带屏蔽）<br />2) 菊花链末端加 120 Ω 终端电阻<br />3) 换总线中继器                                                                       |
| 15 颗都通但偶尔抖     | 5V 供电不足                                                     | 桌面电源限流 3 A 不够，换 5 A 电源                                                                                                        |

### 1.2 单舵机异常

| 现象             | 可能原因                   | 怎么办                                                |
| -------------- | ---------------------- | -------------------------------------------------- |
| 通电就抖           | 1) 校准数据错<br />2) 齿轮卡死  | 1) 重做 calibration.json<br />2) 退换                  |
| 通电就嗡           | 1) 零位偏太多<br />2) 缺油    | 1) 重新校零位<br />2) 拆开加润滑脂（Kluber P125）               |
| 转动有异响          | 1) 齿轮磨损<br />2) 轴承坏    | 退换                                                 |
| 转动不到位          | 1) 行程设错<br />2) 死区太大   | 1) 检查 min/max<br />2) 减死区                          |
| 转动滞后           | 1) PID 不对<br />2) 总线延迟 | 1) 调 PID（**飞特与 Dynamixel 不同**）<br />2) 用 SYNC_READ |
| 8.4V 满电堵转后壳体发热 | **超规格**                | **改 5V 限压测试**；**长时堵转不要超过 10s**                     |

### 1.3 15 颗舵机同步

| 现象       | 可能原因                 | 怎么办                                      |
| -------- | -------------------- | ---------------------------------------- |
| 15 颗动作不齐 | 1) 通信延迟<br />2) 单颗异常 | 1) 用 SYNC_READ（p99 < 1ms）<br />2) 隔离单颗排查 |
| 某些舵机不响应  | 1) ID 冲突<br />2) 线松  | 1) 重新 Scan<br />2) 重插线                   |
| 通电瞬间全部乱抖 | 总线数据冲突               | 1) 检查是否有外部干扰源<br />2) 加屏蔽                |

## 二、电源相关

### 2.1 桌面电源

| 现象                | 可能原因                     | 怎么办                                    |
| ----------------- | ------------------------ | -------------------------------------- |
| 7.5V 适配器不供电       | 1) 适配器坏<br />2) DC 插头不对  | 1) 万用表量空载电压<br />2) 确认 DC 5.5×2.1 插头   |
| 限流保护（电压掉到 5V）     | 15 颗堵转                   | 1) 排除机械卡死<br />2) 改 3D 打印件             |
| 5V PD 适配器给主控供电不稳定 | 1) PD 协议不兼容<br />2) 线材问题 | 1) 换 QC/PD 双协议适配器<br />2) 换原装 Type-C 线 |

### 2.2 2S 电池

| 现象           | 可能原因                                | 怎么办                                                   |
| ------------ | ----------------------------------- | ----------------------------------------------------- |
| 装上电池舵机不动     | 1) 电池没电<br />2) 保险丝烧<br />3) 动力开关没合 | 1) 万用表量电池电压（> 6.6V）<br />2) 换保险丝<br />3) 闭合开关         |
| 跑 5 分钟就低电报警  | 1) 电池容量虚标<br />2) 放电倍率不够            | 1) 换大品牌（淘宝 7.4V 3400mAh 选放电 5C 以上）<br />2) 2C 不够，上 5C |
| 电池鼓包         | **严重事故**                            | **立即停用**！单独存放，联系厂家退换                                  |
| 电池短路（导线碰到一起） | **立即喷火**                            | 灭火毯 / 沙包（**不要用水**）                                    |

## 三、主控相关

### 3.1 Radxa Zero 3W

| 现象               | 可能原因                               | 怎么办                                                                                  |
| ---------------- | ---------------------------------- | ------------------------------------------------------------------------------------ |
| 启动卡在 logo        | 1) SD 卡坏<br />2) 镜像烧错              | 1) 换 SD 卡<br />2) 重烧镜像                                                               |
| 启动后 wlan0 找不到    | Radxa OS 已知问题                      | `sudo modprobe brcmfmac && sudo systemctl restart NetworkManager`                    |
| wlan0 DHCP 抽风    | Radxa Zero 3W 已知 bug               | **先用网线**，WiFi 留到整机阶段                                                                 |
| 串口无 `/dev/ttyS2` | UART2 没启用                          | `sudo raspi-config` → Interface → Serial → Enable (No console)                       |
| I²C 扫描不到 IMU     | 1) 接线错<br />2) 3.3V 没给<br />3) 地址错 | 1) 检查 SDA/SCL/GND/3.3V<br />2) 万用表量 3.3V<br />3) LSM6DSV16X 默认 0x6a，`i2cdetect -y 3` |
| ONNX Runtime 加载慢 | 首次加载要 import                       | 第一次加载慢正常，第二次快                                                                        |

### 3.2 板端服务

| 现象                               | 可能原因                      | 怎么办                                                     |
| -------------------------------- | ------------------------- | ------------------------------------------------------- |
| `robotd` 报 "torque off" 但实际舵机有扭矩 | 误读 reg 40                 | **用 `sim336/OptiDuck` v1.03 之后的新固件**（修了 reg 40 解析 bug）  |
| 摄像头 `/dev/video0` 被 `mediad` 独占  | 视频服务与自建 MJPEG 冲突          | `sim336/OptiDuck` v1.01 用 `report_video.py` 走 GStreamer |
| 推理 p99 > 2ms                     | 1) 散热不良<br />2) 后台进程抢 CPU | 1) 加散热片<br />2) `systemd-run --scope` 固定优先级             |
| 50 Hz 控制环失约                      | 1) 中断延迟<br />2) swap      | 1) 用 `chrt -f 99` 固定优先级<br />2) 关 swap                  |

## 四、3D 打印相关

| 现象        | 可能原因                     | 怎么办                                 |
| --------- | ------------------------ | ----------------------------------- |
| 轴承孔位太紧    | 1) 打印收缩<br />2) 没扩孔      | 用对应外径的铰刀精修（公差 0.05mm）               |
| M2 自攻孔位崩  | 1) 孔太小<br />2) 螺丝质量差     | 1) 用 1.9mm 钻头预扩<br />2) 换 304 不锈钢螺丝 |
| TPU 打印堵嘴  | 1) 温度不对<br />2) 速度太快     | 1) 230°C<br />2) 30 mm/s            |
| TPU 打印件太软 | TPU 85A（不是 95A）          | 换 TPU 95A                           |
| PETG 翘边   | 1) 热床温度不够<br />2) 第一层没压实 | 1) 80°C 热床<br />2) 调 Z 高度           |
| 支撑拆不掉     | 用错支撑类型                   | 改"树状支撑"                             |

## 五、装配相关

| 现象           | 可能原因                           | 怎么办                                          |
| ------------ | ------------------------------ | -------------------------------------------- |
| 8 个 -FT 件装不上 | 用了原版凹舵盘件                       | 必须用 -FT 后缀（适配 HD-1910 凸舵盘）                   |
| 凸舵盘装反        | 凸面方向反                          | 凸面朝身体中线（左右腿）                                 |
| 整机走两步就倒立翻    | 1) 8 个 -FT 件没换<br />2) 髋关节零位偏  | 1) 换 -FT 件<br />2) 重做 calibration.json       |
| 左右腿不同步       | 1) 右腿 direction 错<br />2) 零位偏  | 1) 右腿 direction 设为 -1<br />2) 重做 calibration |
| 头颈装好后摇头不动    | 1) 4 颗 ID 没配好<br />2) 头颈线束没留余量 | 1) 重做 ID 21-25 / 31-34<br />2) 头颈线留 5cm 余量   |
| 嘴部装好后被罩壳压住   | 嘴部行程设错                         | 改 min/max 让嘴张开不受限                            |

## 六、策略相关

| 现象             | 可能原因                | 怎么办                                                |
| -------------- | ------------------- | -------------------------------------------------- |
| ONNX 推理直接摔     | 没用 HD-1910 的 BAM 参数 | **必须用 HD-1910 BAM 参数重训**                           |
| 仿真走得很好，真机走两步就倒 | 电机参数不对              | 用 `LuwuDynamics/xgoduck_rl` 公开的 HD-1910 BAM M6 参数  |
| 仿真走得很慢         | 5V 基准建模             | 改成 2S 电池基准（6.5–8.2V）——**参考 sim336/OptiDuck v1.02** |
| 走直线但转不了方向      | hip_yaw 关节没训到       | 加大 hip_yaw 权重                                      |
| 走两步就震颤         | 仿真/真机饱和率失配          | 加 backlash 域随机化                                    |
| 起来就倒           | 站立任务与走路任务衔接不上       | 用 curriculum learning（先学站立，再学走路）                   |
| IMU 数据是 NaN    | IMU 没接好             | 检查 I²C 地址（0x6a）                                    |

## 七、训练相关（高级）

| 现象           | 可能原因                                      | 怎么办                                                               |
| ------------ | ----------------------------------------- | ----------------------------------------------------------------- |
| 训练 24h 不收敛   | 1) 奖励函数错<br />2) 域随机化太大                   | 1) 简化为"前进速度"奖励<br />2) 减小随机化范围                                    |
| 训练 24h 步态怪异  | 1) URDF 错<br />2) 关节限位错                   | 1) 用 `urdf_to_mjcf` 重新转换<br />2) 检查 calibration.json 的 min/max    |
| 训练后 ONNX 推理慢 | 用了不必要的图优化                                 | ONNX Runtime 默认图优化即可，**不要**用 TensorRT（Radxa Zero 3W 没 NVIDIA GPU） |
| 训练后策略无法部署    | 1) 包含 GPU 算子<br />2) 没做 obs normalization | 1) 全部用 CPU 算子<br />2) ONNX 内含 obs normalization，运行端**不要重复归一化**    |

## 九、紧急回退方案

> 如果某个步骤卡住超过 1 天，**回退到上一步**比硬刚更高效。

```
舵机配 ID 失败 → 换舵机 → 换调试板 → 换 USB 线 → 换电脑
↓
零位校准失败 → 拆下来重装 → 重做 calibration.json → 换舵机
↓
单舵机响应 → 用 URT-2 自带软件 → 用 mock_feetech.py
↓
总线不通 → 检查线序 → 减总线长度 → 加终端电阻
↓
整机集成失败 → 回到单腿测试 → 回到悬吊测试 → 回到单舵机测试
```
