# 策略部署

> **本教程原则**：**不能直接用官方原版 ONNX**——必须用 HD-1910 的 BAM 参数重训。  
> **来源**：`pollen-robotics/microduck_rl` + `JoyandAI/microduck_rl` + `LuwuDynamics/xgoduck_rl` 三源校验。

---

## 一、策略契约（与官方一致）

| 维度    | 官方 Microduck                        | 本复刻               |
| ----- | ----------------------------------- | ----------------- |
| 观测维度  | 61                                  | **同**（沿用）         |
| 动作维度  | 14                                  | **同**（嘴部独立，不参与步态） |
| 控制环频率 | 50 Hz（20 ms 一拍）                     | **同**             |
| 仿真    | MuJoCo                              | **同**             |
| 训练框架  | mjlab + PPO（推荐）/ rhoban/duck_ros 旧版 | **沿用**            |
| 模型格式  | ONNX                                | **同**             |
| 板上推理  | ONNX Runtime                        | **同**             |

> 💡 **观测 61 维包含什么**（来自 `unergybot/microduck-ubot` 仓库的关节参数文档）：
>
> - 关节位置 14 维（每腿 5 + 头颈 4 = 14，**嘴部不在观测里**）
> - 关节速度 14 维
> - 上一时刻动作 14 维
> - 机身姿态（IMU 欧拉角）3 维
> - 机身角速度（IMU 陀螺仪）3 维
> - 上一时刻指令的 base lin vel × base ang vel = 13 维  
>   = **61 维**（含 1 个时间步 / 命令相关）
>
> 嘴部 ID 1 单独控制，**不进策略**。

## 二、为什么必须重训

### 2.1 力矩曲线不同

| 维度           | XL330-M288-T（原版）                   | HD-1910-C001（复刻）              |
| ------------ | ---------------------------------- | ----------------------------- |
| 额定电压         | 3.7–6.0 V（**实际 6.6–8.2 V，超压 37%**） | 4–8.4 V（**实际 6.6–8.2 V，额定内**） |
| 堵转扭矩         | 0.97 N·m（@ 5V 基准）                  | **1.51 N·m**（修正后 v1.02）       |
| 齿比           | 288:1                              | 320:1                         |
| 齿隙（backlash） | 未知                                 | 0.002 rad（实测）                 |
| PWM 斜率       | 未知                                 | 未知（需自测）                       |

> ⚠️ **`sim336/OptiDuck` v1.02 重要发现**：早期训练配置曾误按"5.0 V 稳压轨"建模（**那是台架桌面电源，不是整机**）。5V 基准会让仿真舵机比真机**弱 1.48 倍**（7.4/5.0），这正是长期存在的仿真/真机饱和率失配（仿真 21% vs 真机 4.2%）的根因。**已在 v1.02 中修正**——你训练时**直接用 2S 电池基准（6.5–8.2V）**。

### 2.2 8 个连杆件差异

HD-1910 是**凸舵盘**，原版 8 个连杆件装不上。**新连杆件的几何 / 惯量 / 重心都不同**，必须重训。

## 四、训练流程

### 4.1 任务定义

`microduck_rl` 默认提供 5 个任务（**全部开源**）：

| 任务          | 文件                   | 说明            |
| ----------- | -------------------- | ------------- |
| `walk`      | `tasks/walk.py`      | 前进 / 后退 / 左右转 |
| `standup`   | `tasks/standup.py`   | 趴下后站起来        |
| `head_idle` | `tasks/head_idle.py` | 头部随机摆动        |
| `sit`       | `tasks/sit.py`       | 坐下            |
| `kick_ball` | `tasks/kick_ball.py` | 踢球            |

> 来源：`pollen-robotics/microduck_rl`（Apache-2.0）

### 4.2 启动训练

```bash
cd microduck_rl

# 训练 walk 策略（24h 跑完）
uv run train.py \
    --task walk \
    --robot microduck \
    --num_envs 4096 \
    --total_timesteps 1_000_000_000 \
    --device cuda
```

### 4.3 域随机化（Domain Randomization）

`microduck_rl` 默认开：

```python
domain_randomization = {
    "mass": "uniform(0.8, 1.2) * nominal",
    "friction": "uniform(0.5, 1.1)",
    "motor_strength": "uniform(0.9, 1.1) * nominal",
    "motor_offset": "uniform(-0.05, 0.05) rad",
    "joint_damping": "uniform(0.5, 2.0) * nominal",
    "imu_latency": "uniform(0, 5) ms",
    "imu_noise": "gaussian(0, 0.01) rad/s",
    "backlash": "uniform(0.0, 0.005) rad",
}
```

### 4.4 导出 ONNX

```bash
uv run export_onnx.py \
    --task walk \
    --checkpoint logs/walk/best.pt \
    --output ../policies/walk.onnx
```

> ONNX 文件约 **3–5 MB**（actor 网络 + obs normalization）。

## 五、Sim-to-Real 四层保护

> 来自 `microduck-lumi` 项目自身的训练章节（已与上游对齐）。

1. **BAM 电机模型**：用 HD-1910 实际参数（kt=0.692 N·m/A，来自 `sim336/OptiDuck` v1.02 台架实测 R²=0.998）；
2. **Domain randomization**：质量、阻尼、随机扰动；
3. **Backlash 变体**：齿轮间隙（HD-1910 实测 0.002 rad）；
4. **真机前 `infer_policy.py` 契约重演**：
   ```bash
   python3 scripts/infer_policy.py --policy policies/walk.onnx --replay
   # 检查输出动作是否在舵机行程内
   ```

## 六、板载部署

### 6.1 ONNX 推理（CPU）

```python
# infer.py
import onnxruntime as ort
import numpy as np

session = ort.InferenceSession('policies/walk.onnx')

def policy(obs):
    """61 维观测 → 14 维动作"""
    obs = obs.astype(np.float32)
    action = session.run(None, {'obs': obs[None, :]})[0][0]
    return action  # shape (14,)
```

### 6.2 50 Hz 控制环

```python
# control_loop.py
import time
import numpy as np
from policy import policy
from feetech import FeetechBus

bus = FeetechBus('/dev/ttyS2', 1_000_000)
ids = [11, 12, 13, 14, 15, 21, 22, 23, 24, 25, 31, 32, 33, 34]
DT = 0.02  # 50 Hz

obs = np.zeros(61)
while True:
    t0 = time.monotonic()

    # 1. 读观测（关节位置 + IMU）
    joint_pos = bus.sync_read_present_position(ids)
    imu = read_imu()  # I²C 读 LSM6DSV16X
    obs = build_obs(joint_pos, imu, last_action)

    # 2. 推理（ONNX）
    action = policy(obs)

    # 3. 写目标
    targets = rad_to_pulse(action)  # 14 维 → 14 个 0-4095
    bus.sync_write_goal_position(ids, targets)

    # 4. 等下一拍
    elapsed = time.monotonic() - t0
    if elapsed < DT:
        time.sleep(DT - elapsed)
    else:
        print(f"WARNING: loop took {elapsed*1000:.1f}ms")
```

### 6.3 推理性能实测（Radxa Zero 3W）

来自 `sim336/OptiDuck` v1.03 实测（**真机 1000 步实测**）：

| 指标         | 值            |
| ---------- | ------------ |
| p50 延迟     | **0.367 ms** |
| p95 延迟     | 0.761 ms     |
| p99 延迟     | 0.836 ms     |
| max 延迟     | 1.069 ms     |
| over 20 ms | **0**（无超时）   |
| 周期占比       | 约 1.8%       |

> 💡 **50 Hz 周期 20 ms**，p99 0.836 ms 远低于周期上限，**控制环绝对安全**。

## 七、不重训的妥协方案（仅供玩耍）

> ⚠️ **官方不推荐**——直接插即用官方 ONNX 必摔。

如果你只想"看起来像在走"，**不管走得多丑**：

1. 下载官方 9 个 ONNX（`pollen-robotics/microduck_rl` 仓库 releases）；
2. 把动作映射到 HD-1910 行程（**硬裁剪**）；
3. 配上慢速时钟（每拍乘 0.3）；
4. 鸭子会"看起来像在抽搐式前进"——**不算会走**。

> 这个方案 `emwstudio/DuckEMW` 仓库用单张 4090D 训出跳舞策略（但也是 XL330），**仅供娱乐**。

## 九、训练常见坑

| 现象             | 根因            | 怎么办                                               |
| -------------- | ------------- | ------------------------------------------------- |
| 仿真走得很好，真机走两步就倒 | 电机参数不对        | 用 HD-1910 BAM 参数（`LuwuDynamics/xgoduck_rl`）       |
| 仿真走得很慢         | 5V 基准建模       | 改成 2S 电池基准（6.5–8.2V），**参考 sim336/OptiDuck v1.02** |
| 走直线但转不了方向      | hip_yaw 关节没训到 | 加大 hip_yaw 权重                                     |
| 走两步就震颤         | 仿真/真机饱和率失配    | 加 backlash 域随机化                                   |
| 起来就倒           | 站立任务与走路任务衔接不上 | 用 curriculum learning（先学站立，再学走路）                  |
| IMU 数据是 NaN    | IMU 没接好       | 检查 I²C 地址（0x6a）                                   |
